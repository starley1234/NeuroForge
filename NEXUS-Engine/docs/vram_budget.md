# Бюджет VRAM и соответствие таблице спецификации

Расчёт: `nexus vram --preset <profile>` (`nexus/eval/vram.py`), аналитический,
по числу параметров архитектуры, BF16 + 8-bit оптимизатор + 50 % экспертов
на CPU-offload, чанк L = 128, batch 2.

## Профиль `rtx5060` (по умолчанию)

| Компонент | Значение | VRAM |
| :-- | :-- | --: |
| Активные параметры | 1.36B (d = 1536, 24 слоя, 1+4 экспертов) | 2.54 ГБ |
| Веса MoE (32 эксперта, 7.7B) | половина в VRAM | 6.75 ГБ |
| FNO-критик | ~32M (modes 12, width 48, depth 4) | 0.06 ГБ |
| Оптимизатор 8-bit | 2 состояния на активный вес | 2.54 ГБ |
| Активации | L = 128, batch 2, 24 слоя | 0.32 ГБ |
| TTT-состояние | не зависит от длины контекста | 0.003 ГБ |
| **Итого** | | **12.21 ГБ** |

## Профиль `rtx5060-compact`

14 экспертов вместо 32 → суммарные веса MoE ≈ 3.6B, как в таблице исходного ТЗ.
Итого **8.41 ГБ**, запас 7.6 ГБ — можно поднять batch или окно внимания.

## Про расхождения с исходной таблицей

Таблица ТЗ внутренне противоречива: раздел 3 задаёт «1 общий + 4 активных из 32»,
а таблица VRAM — «8 экспертов, всего 3.6B, активны 1.3B». Одновременно выполнить
оба условия нельзя: при 33 экспертах и 1.3B активных суммарные веса неизбежно
≈ 7.7B. Реализация выбирает **маршрутизацию из раздела 3** как основную
(`rtx5060`) и добавляет вариант под цифры таблицы (`rtx5060-compact`).
Итоговый расход в обоих случаях укладывается в 16 ГБ с запасом.

## Как ужаться ещё

| Приём | Экономия |
| :-- | :-- |
| `moe_offload = 0.75` | −3.4 ГБ |
| QLoRA (nf4) на экспертах | −4…5 ГБ |

| `chunk = 64`, grad-checkpointing | −0.2 ГБ активаций |
