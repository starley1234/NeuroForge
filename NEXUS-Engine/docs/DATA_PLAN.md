# План данных: чем кормить NEXUS

Коротко: **готового датасета под нашу задачу не существует**. Есть три пласта,
которые нужно сложить: (1) чужие открытые CAD-корпуса, (2) собственный
верифицированный синтез, (3) дистилляция из сильной LLM через MCP с физической
проверкой. Ниже — что брать, в каком порядке и почему.

---

## 1. Что есть в мире (проверено, декабрь 2025 → апрель 2026)

### CAD как код — основное

| Датасет | Объём | Лицензия | Комментарий |
| :-- | :-- | :-- | :-- |
| [Zero-to-CAD-1M](https://huggingface.co/datasets/ADSKAILab/Zero-To-CAD-1m) | 1 000 000 исполняемых программ | см. карточку | Сгенерирован LLM **внутри среды с обратной связью**; покрывает булевы, фаски, скругления, лофты, свипы, оболочки — то есть ровно тот словарь операций, что нужен. | [CAD-Coder](https://huggingface.co/datasets/gudo7208/CAD-Coder) | 250k сэмплов, 8.2k «high», 1.5k CoT | **Apache-2.0** | Единственный крупный text→CadQuery с коммерчески чистой лицензией **и цепочками рассуждений**. Брать первым. |
| [BenchCAD](https://huggingface.co/datasets/BenchCAD/BenchCAD) | 17.9k программ, 106 семейств деталей | CC-BY-4.0 | Промышленные семейства (шестерни, пружины, свёрла) + QA + edit-bench. Лучший held-out бенчмарк. |
| [thingiverse-openscad](https://huggingface.co/datasets/redcathode/thingiverse-openscad) | 7.4k пар, 26 МБ | CC-BY-NC-SA | **Единственный** публичный корпус именно OpenSCAD. Мал и шумен, но даёт «человеческий» стиль языка. NC → только research. |
| [Text2CAD](https://huggingface.co/datasets/SadilKhan/Text2CAD) | ~170k аннотаций | CC-BY-NC-SA | Классика, но 605 ГБ вложений и NC-лицензия. |
| [GenCAD-Code](https://huggingface.co/datasets/CADCODER/GenCAD-Code) | 163k изображение→код | см. карточку | Понадобится, когда подключим визуальный энкодер. |

Историческая база (DeepCAD 178k, Fusion 360 Gallery 8.6k) сегодня проигрывает
по размеру и покрытию операций; Fusion 360 к тому же под «только research»
лицензией в стиле ImageNet.

### Геометрия и симуляции

| Датасет | Объём | Лицензия | Зачем нам |
| :-- | :-- | :-- | :-- |
| [SimJEB](https://simjeb.github.io) | 381 кронштейн × 4 нагрузочных случая | ODC-BY (CAD — NC) | Честный промышленный FEM: **валидация нашего hex-решателя** и FNO-суррогата. |
| [DeepJEB](https://www.narnia.ai/dataset) | 2138 деталей, поля σ и собственные частоты | ODC-BY | В 5.6× больше SimJEB, знаковые напряжения — готовые метки для критика. |

### Математика и рассуждения

| Датасет | Объём | Лицензия | Комментарий |
| :-- | :-- | :-- | :-- |
| [OpenMathReasoning](https://huggingface.co/datasets/nvidia/OpenMathReasoning) | 540k задач, 3.2M CoT, 1.7M TIR | CC-BY-4.0 | Есть решения **с инструментами** (TIR) — прямой аналог нашего латентного цикла с FNO-критиком. |
| [OpenR1-Math-220k](https://huggingface.co/datasets/open-r1/OpenR1-Math-220k) | 225k, 4.2 ГБ | Apache-2.0 | Решения R1 с автоверификацией ответа: можно оставить только доказанно верные. |
| **Наш `mathgen`** | сколько нужно | MIT | 13 типов инженерного счёта, ответ считается формулой. Ошибок в метках нет **по построению**. |

Мой комментарий: общая олимпиадная математика нам нужна дозированно (10–15 %
токенов). Модели полезнее уметь считать момент затяжки и размерную цепь, чем
решать функциональные уравнения. Поэтому основной математический корпус —
собственный генератор, а внешние датасеты идут как «прививка» общего
рассуждения перед RL-фазой.

## 2. Что делаем сами (уже реализовано)

### 2.1 Маховик OpenSCAD → FEM

`nexus flywheel` уже даёт кортежи `{ТЗ + нагрузки → код → 3D → FEM}` в любом
количестве. С новым hex-МКЭ метки стали физически корректными, а не
суррогатными. Стоимость — только CPU-время.

### 2.2 Верифицированная инженерная математика

```bash
nexus gen-math -n 50000 --out artifacts/math/engineering_math.jsonl
nexus gen-math --list-kinds
```

13 генераторов: изгиб и прогиб консоли, момент затяжки, напряжение в болте,
тепловое расширение, масса детали, момент инерции сечения, размерная цепь
(worst-case и RSS), время печати, посадка с натягом, зубчатая пара,
устойчивость по Эйлеру, срез штифта. Каждый сэмпл — задача, пошаговое решение и
числовой ответ, который **проверяется формулой** (`MathSample.check`).

### 2.3 MCP-сервер: наш движок как инструменты для чужой LLM

```bash
nexus mcp --list-tools           # посмотреть контракты
nexus mcp                        # stdio-сервер (JSON-RPC 2.0, без зависимостей)
```

```jsonc
// Claude Desktop / Kiro / OpenAI Agents SDK
{"mcpServers": {"nexus": {"command": "python", "args": ["-m", "nexus.mcp.server"]}}}
```

Инструменты: `scad_compile`, `scad_analyze` (масса, инерция, manifold, стенки,
свесы, ЧПУ), `fem_analyze` (настоящий МКЭ), `score_design` (физическая награда),
`propose_variation`, `math_problem`, `record_sample`, `engine_info`.

Отличие от существующих OpenSCAD-MCP серверов (их уже несколько: сборка STL и
рендер картинок для vision-модели) — у нас в петлю попадает **физика**: масса,
запас прочности, технологичность. Модель видит не «похоже на картинку», а
«запас 1.4 при требуемом 2.0».

### 2.4 Дистилляция с верификацией

```bash
# любой внешний CLI как учитель — ключи остаются у вас
nexus collect --teacher command --command "claude -p" -n 500 --attempts 3

# локальная модель
nexus collect --teacher hf --hf-model Qwen/Qwen2.5-Coder-7B-Instruct -n 500

# самоулучшение после первого обучения
nexus collect --teacher nexus --ref production -n 1000
```

Цикл: ТЗ → учитель пишет SCAD → движок считает → если не прошло, замечания
(«не компилируется», «стенка 0.4 мм», «запас 1.3 при требуемом 2.0»)
возвращаются учителю → до `--attempts` попыток → принимается только то, что
прошло порог награды. В корпус пишется и финальный код, и **траектория
исправлений** — это ценнее готового ответа, потому что учит модель чинить свои
ошибки.

Офлайн-прогон на шаблонном учителе: 12 задач, 100 % приёмка, средняя награда
4.38 из 5 — конвейер работает, осталось подставить сильного учителя.

## 3. Рекомендуемые миксы

`nexus datasets mixes` печатает готовые строки-источники.

| Микс | Состав | Когда |
| :-- | :-- | :-- |
| `bootstrap` | 45 % маховик, 25 % mathgen, 25 % CAD-Coder, 5 % встроенный | первый прогон, всё локально и лицензионно чисто |
| `engineering` | 30 % маховик, 25 % Zero-to-CAD, 15 % CAD-Coder, 15 % mathgen, 10 % OpenR1-Math, 5 % документация | основное обучение |
| `reasoning` | 40 % OpenMathReasoning, 30 % OpenR1-Math, 30 % mathgen | добавка перед RL-фазой |

```bash
nexus train-lm --source "$(nexus datasets mixes | grep -A0 '^engineering' | cut -d' ' -f2-)"
# или явно:
nexus train-lm --source "mix:flywheel:artifacts/flywheel=0.45,mathgen:20000=0.25,builtin:engineering=0.30"
```

Источник `mix:` читает потоки лениво и перемешивает по весам, так что терабайтные
HF-датасеты не нужно скачивать целиком — работает `streaming`.

## 4. Порядок действий (что бы делал я)

| Неделя | Действие | Результат |
| :-- | :-- | :-- |
| 1 | `nexus flywheel -n 50000` (сетка 24, hex-FEM на подвыборке) + `nexus gen-math -n 100000` | ~200–400 МБ своих чистых данных, 0 ₽ |
| 1 | Подключить MCP к Claude/GPT, `nexus collect --teacher command -n 2000` | 2k верифицированных «человеческих» решений с траекториями |
| 2 | Скачать CAD-Coder (Apache) + BenchCAD (CC-BY), написать транслятор CadQuery→OpenSCAD для подмножества операций | +100k пар с чистой лицензией |
| 2 | Обучить BPE на 16k и первый прогон `train-lm --source mix:bootstrap` | базовая модель, метрики в реестре |
| 3 | Zero-to-CAD-1M в streaming-режиме, 100k диверсифицированный сабсет | покрытие операций CAD |
| 3 | SimJEB + DeepJEB → валидация hex-решателя и обучение FNO на реальных полях | доверие к наградам |
| 4 | `nexus collect --teacher nexus` (самоулучшение) + `nexus rl` | замыкание маховика |

Оценка объёма для 1.3B: 10–20 млрд токенов «в идеале», но реалистично на одной
RTX 5060 — 1–3 млрд, из которых 60 % должно быть узкодоменным (CAD-код + физика
+ инженерная математика). Chinchilla-оптимум здесь вторичен: важнее чистота
меток, чем объём.

## 5. Юридические границы (важно)

* **Коммерчески чистое**: CAD-Coder (Apache-2.0), OpenR1-Math (Apache-2.0),
  OpenMathReasoning (CC-BY-4.0), BenchCAD (CC-BY-4.0), наш маховик и mathgen (MIT).
* **Только исследования**: Text2CAD, thingiverse-openscad (NC), Fusion 360 Gallery,
  CAD-файлы внутри SimJEB.
* **Дистилляция**: результаты работы чужой модели ограничены её ToS. Для
  открытых весов (Qwen, Llama, DeepSeek) обычно можно, для закрытых API —
  читайте условия перед публикацией весов. Наш `collect` пишет источник учителя
  в метаданные, чтобы потом можно было отфильтровать.
* Скрейпинг Printables/Thingiverse: файлы под CC, но метаданные и ToS площадки —
  отдельный вопрос; безопаснее брать готовый HF-датасет с атрибуцией.

## 6. Мои комментарии без прикрас

1. **Главная ценность — не чужие датасеты, а наш верификатор.** Любой корпус
   CAD-кода можно прогнать через `score_design` и получить метки прочности,
   технологичности и массы, которых нет ни в одном публичном датасете. Это наше
   единственное реальное преимущество, и оно масштабируется на CPU.
2. **OpenSCAD-корпусов почти нет, CadQuery-корпусов много.** Дешевле написать
   транслятор подмножества CadQuery→OpenSCAD (примитивы, булевы, трансформации,
   extrude — 300–500 строк), чем ждать появления данных. Тогда открываются
   Zero-to-CAD (1M), CAD-Coder (250k), BenchCAD (18k).
3. **Дистилляция без верификации — путь к красивому мусору.** Модель-учитель
   пишет правдоподобный SCAD, который не собирается или ломается под нагрузкой.
   Порог по награде и цикл исправлений важнее выбора учителя.
4. **Траектории ценнее ответов.** Пара «сломанная деталь → замечание → починка»
   учит тому, чего нет в готовых датасетах, и напрямую готовит модель к
   RL-фазе с теми же наградами.
5. **Математику берём прицельно.** Инженерный счёт генерируем сами (метки
   идеальны), общий математический корпус добавляем 10–15 % для переносимости
   рассуждений.
6. **Реалистичный минимум для первого осмысленного результата**: 50k деталей
   маховика + 100k математики + 2k дистиллированных с проверкой + CAD-Coder.
   Это ~1–2 дня CPU и один вечер работы с API учителя.
