# План: своя модель для text-to-3d.ru

Отталкиваемся от факта: у вас **работающий продукт с 1000+ параметрическими
шаблонами, слайдерами параметров и инженерными расчётами по ГОСТ/DIN**. Это не
стартовая позиция «догоняем Zoo и AdamCAD» — это позиция «у нас есть то, чего
у них нет: домен, данные и живой трафик». Ниже — что делать по шагам.

---

## 0. Что у вас уже сильнее конкурентов

| Актив | Почему это важно |
| :-- | :-- |
| Сотни пар «запрос → код → рендер» и они прибывают каждый день | ровно те данные, за которыми охотятся все; у Zoo и AdamCAD они есть, но не по вашему домену и не на русском |
| 1000+ параметрических шаблонов с именованными параметрами | размеченная структура «что в детали можно менять» — этого нет ни в одном публичном датасете |
| Правки параметров пользователями | сигнал предпочтений: что модель угадала, а что человек пошёл исправлять |
| Живой трафик | и источник данных, и площадка для A/B, и канал дистрибуции |
| Вы уже платите за большую LLM | значит, вы уже оплачиваете учителя для дистилляции — данные накапливаются в любом случае |

Главный вывод: **своя модель нужна не чтобы «сделать лучше, чем GPT», а чтобы
снять зависимость от чужого API, обвалить себестоимость генерации и получить
актив, который можно развивать в любую сторону.**

---

## 1. Два трека, чтобы не блокировать продукт

Не смешивать. Иначе исследование съест продукт.

| Трек | Что это | Срок до пользы | Риск |
| :-- | :-- | :-- | :-- |
| **Продуктовый** | LoRA-дообучение открытой модели (Qwen2.5-Coder-7B/14B) на вашем корпусе | 2–4 недели | низкий |
| **Исследовательский** | наша архитектура NEXUS, обучение с нуля | месяцы | высокий |

Продуктовый трек даёт «свою модель» быстро: веса ваши, работает офлайн,
дообучается на вашем домене. Исследовательский идёт параллельно и подключается,
когда обгонит по метрикам. Инфраструктура (реестр, приёмка, API, физика) уже
общая для обоих.

## 2. Шаг 1 (эта неделя): начать собирать правильные данные

Сейчас в БД лежит результат, но не лежит **процесс**. А учиться нужно на процессе.

Что добавить в логирование на сайте:

```sql
ALTER TABLE stl_items
  ADD COLUMN llm_model      VARCHAR(64),    -- какая модель сгенерировала
  ADD COLUMN prompt_raw     TEXT,           -- точный текст запроса пользователя
  ADD COLUMN attempt_no     INT DEFAULT 1,  -- номер попытки для этого запроса
  ADD COLUMN parent_item_id INT NULL,       -- если это перегенерация/правка
  ADD COLUMN param_edits    JSON,           -- какие слайдеры и как менял человек
  ADD COLUMN downloaded     TINYINT(1) DEFAULT 0,
  ADD COLUMN user_verdict   ENUM('ok','broken','not_what_asked') NULL;
```

Три кнопки в интерфейсе, которые превращают трафик в разметку:

1. **«Напечатал, подошло» / «Не подошло»** — прямая метка качества;
2. **«Почини»** с полем «что не так» — порождает пару «сломано → исправлено»,
   самый ценный тип данных;
3. **«Усилить под нагрузку»** — запускает наш расчёт и порождает пример
   «деталь → усиленная деталь».

Стоимость: пара дней работы. Отдача: через месяц у вас корпус, которого нет ни
у кого.

## 3. Шаг 2 (эта же неделя): встроить физику в продукт

Это одновременно фича для пользователей и генератор меток.

```bash
# на сервере сайта
nexus serve --host 127.0.0.1 --port 8000 --api-key $KEY
```

В карточке модели показывать бейдж после генерации:

```
✅ Замкнутая деталь · масса 41 г (PLA) · стенка 2.4 мм
⚠️ Свесы 38° — потребуются поддержки
✅ Запас прочности 3.1 при нагрузке 150 Н
```

Вызов из PHP — один POST:

```php
$r = json_decode(file_get_contents('http://127.0.0.1:8000/v1/analyze', false,
  stream_context_create(['http' => [
    'method' => 'POST',
    'header' => "Content-Type: application/json\r\nAuthorization: Bearer $KEY\r\n",
    'content' => json_encode(['code' => $scad, 'material' => 'pla',
                              'force' => [0, 0, -150], 'grid' => 20])]])), true);
```

Что это даёт: (1) отличие от конкурентов уже сегодня, (2) физическая метка на
каждую модель в базе, (3) автоматический отсев брака до показа пользователю.

## 4. Шаг 3 (недели 1–2): корпус и базовые метрики

```bash
mysqldump -u user -p site stl_items > stl_items.sql
nexus ingest sql:stl_items.sql --out artifacts/ingest --grid 20
nexus render-dataset --input artifacts/ingest/dataset.jsonl --out artifacts/vision --size 512
```

Сразу же — **эталонный набор запросов**: 200–300 реальных промптов из логов,
отобранных по частотности (клипсы, заглушки, держатели, переходники, корпуса).
Это ваш главный бенчмарк, а не публичные датасеты.

```bash
nexus bench --model "command:<ваш вызов большой LLM>" --prompts real_prompts.txt \
            --out artifacts/bench/baseline
```

Так вы получите **базовую линию**: какой процент генераций текущей большой LLM
вообще компилируется, сколько проходит manifold, какая средняя масса. Дальше всё
меряется относительно этой линии.

## 5. Шаг 4 (недели 2–4): своя модель, продуктовый трек

```bash
# 1. экспорт в chat-формат (с физикой в ответе и примерами ремонта)
nexus export-sft --source jsonl:artifacts/ingest/dataset.jsonl \
                 --source jsonl:artifacts/collected/dataset.jsonl --out artifacts/sft

# 2. LoRA поверх современной открытой модели — веса ваши (см. docs/LORA.md)
python scripts/train_lora.py --data artifacts/sft --preset qwen3-coder-8b \
       --epochs 3 --batch-size 2 --grad-accum 8 --seq-len 4096

# 3. сравнение с большой LLM на ваших же запросах
nexus bench --model "command:python serve_lora.py" \
            --model "command:<большая LLM>" \
            --prompts real_prompts.txt --out artifacts/bench/round1
```

Критерий переключения (жёсткий, без самообмана):

| Метрика | Порог для 10 % трафика | Для 100 % |
| :-- | :-- | :-- |
| `compile_rate` | ≥ 0.9 от уровня большой LLM | ≥ 1.0 |
| `manifold_rate` | ≥ 0.85 от уровня | ≥ 1.0 |
| Доля правок слайдеров после генерации | не выше базовой +10 % | не выше базовой |
| Время ответа | ≤ 10 с | ≤ 7 с |
| Себестоимость запроса | — | ниже API в 5+ раз |

Роутер решает задачу постепенного перехода: частые простые классы (клипсы,
заглушки, шайбы, держатели) — своя модель; сложные (редукторы, ЖРД, купола) —
большая LLM. Со временем граница двигается.

## 6. Шаг 5 (месяц 2): маховик самоулучшения

```bash
# сбор данных с проверкой: большая LLM пишет, движок проверяет, брак чинится
nexus collect --teacher command --command "<большая LLM>" -n 2000 --attempts 3

# дообучение своей модели на проверенном
nexus train-lm --resume production --source "jsonl:artifacts/collected/dataset.jsonl#text" \
               --val-source "jsonl:artifacts/ingest/val.jsonl#text" \
               --physics --lr 5e-5 --max-steps 5000 --eval-every 250 --patience 4

# RL на физических наградах — то, чего нет ни у кого
nexus rl --steps 200
```

Здесь появляется настоящее отличие: конкуренты награждают модель за «похоже на
картинку», вы — за «деталь держит нагрузку и печатается».

## 6.1 Готовая фича прямо сейчас: подбор под нагрузку

`nexus optimize` уже работает и не требует обученной модели: берёт ваш
параметрический шаблон, крутит силовые параметры (толщины, рёбра) с настоящим
МКЭ на каждом шаге и возвращает самый лёгкий вариант, который держит.
На кронштейне: −34 % массы за 2.3 с, габариты и отверстия не тронуты.
Подробности и остальные шаги — [WOW_PLAN.md](WOW_PLAN.md).

## 7. Шаг 6 (месяц 3+): то, что нельзя скопировать быстро

1. **Автопараметризация как обучаемая задача.** У вас она уже есть в продукте —
   значит, есть данные «код → набор параметров». Модель, которая сразу пишет код
   с правильными параметрами и подписями, экономит вам шаг генерации.
2. **Ремонт и усиление детали** — отдельный режим («сделай стенку толще, чтобы
   держало 300 Н»), где физика в цикле обязательна.
3. **Офлайн-версия для предприятий**: ваша модель + движок в закрытом контуре,
   без интернета. Это то, что Zoo и AdamCAD как облачные сервисы предложить не
   могут в принципе.
4. **Своя витрина API** для интеграторов и слайсеров.

## 8. Экономика: зачем это вообще

Грубая прикидка, подставьте свои цифры:

| Показатель | Большая LLM | Своя модель (200M–1.5B на RTX 5060 Ti) |
| :-- | :-- | :-- |
| Стоимость генерации | оплата за токены каждому запросу | амортизация железа |
| Задержка | зависит от чужого API | локально, без сети |
| Доступность | зависит от провайдера и санкций | ваша |
| Дообучение под домен | недоступно | в любой момент |
| Себестоимость при росте трафика | растёт линейно | почти не растёт |

Точка окупаемости считается просто: `месячные расходы на API` против
`стоимость GPU + время инженера`. При сотнях генераций в день своя модель
обычно окупается за месяцы, а не годы.

## 9. Патенты: что важно знать (не юридическая консультация)

Разбор [патентного ландшафта AI-FEA](https://www.patsnap.com/resources/blog/articles/ai-accelerated-fea-technology-landscape-2026/)
выделяет четыре кластера. Нас касаются два:

| Кластер | Кто | Суть заявленного |
| :-- | :-- | :-- |
| 1. FEM как датасет, ANN как машина вывода | академические работы, широкая практика | суррогат обучается на результатах FEM и заменяет вызовы решателя |
| 2. Оптимизация геометрии нейросетью | **Bosch, EP 2025** | предсказание метрик вместо расчёта их через FEM в цикле оптимизации |
| 2. Синтез конструкций | **Pratt & Whitney Canada, US 2025** | генерация 2D/3D конструкций двигателей из ИИ-моделей, обученных на исторических FEM-данных |
| 3. ML-планирование параллельных расчётов | X Development, WO 2021 | предсказание оптимальной схемы распараллеливания |

Практические выводы:

1. **Территория.** Патенты действуют там, где выданы. EP-патент Bosch действует
   в валидированных странах Европы, US-патент P&W — в США. Для сервиса,
   работающего в РФ и на российских пользователей, прямого риска нарушения
   этих патентов нет. Он появляется при выходе на рынки ЕС/США.
2. **Патентуются формулы, а не идеи.** «Обучать сеть на данных FEM» — концепция
   с огромным объёмом прежних публикаций (суррогатные модели с 1990-х, PINN
   2019, нейрооператоры 2020, открытый PhysicsNeMo). Широкая формула такого
   уровня нежизнеспособна; реальные притязания узкие и привязаны к конкретному
   применению — например, к оптимизации геометрии в конкретном цикле или к
   конструкциям авиадвигателей.
3. **Наш случай отличается принципиально.** Ключевое в патентах кластера 2 —
   **убрать решатель из цикла** и заменить его предсказанием. У нас наоборот:
   МКЭ считается по-настоящему на каждом запросе и служит источником истины, а
   нейросетевой суррогат (FNO) — вспомогательный и пока даже не обучен. Мы
   ускоряем не расчёт, а написание кода детали.
4. **Что стоит соблюдать:**
   * не заявлять в маркетинге «заменяем FEM», «предсказываем прочность вместо
     расчёта» — держаться формулировки «расчёт выполняется, ИИ помогает писать
     геометрию»;
   * не лезть в авиадвигательную тематику как в заявленное применение;
   * держать проект открытым: публичный репозиторий с датами коммитов — это
     защитная публикация, которая мешает третьим лицам запатентовать то же
     самое после вас;
   * лицензии сторонних компонентов: OpenSCAD и CalculiX — GPL, поэтому мы
     вызываем их как внешние процессы, а не линкуем; NC-лицензированные датасеты
     (Text2CAD, thingiverse-openscad) в коммерческое обучение не берём;
   * при выходе на ЕС/США — заказать точечный FTO-поиск по формулам EP-заявки
     Bosch 2025 и US-заявки Pratt & Whitney 2025; это несколько сотен долларов
     и снимает вопрос.
5. **Обратная сторона.** Если вы первыми сделаете «физически верифицированную
   генерацию CAD-кода», это само по себе патентоспособно. Как минимум стоит
   зафиксировать приоритет публикацией (репозиторий, статья) — это дёшево и
   защищает от чужих притязаний.

## 10. Что делать прямо на этой неделе

```bash
# 1. импорт того, что уже есть
mysqldump -u user -p site stl_items > stl_items.sql
nexus ingest sql:stl_items.sql --out artifacts/ingest --grid 20
cat artifacts/ingest/stats.json           # сколько реально валидного

# 2. базовая линия по вашим же запросам
nexus bench --model "command:<вызов вашей LLM>" --prompts real_prompts.txt \
            --out artifacts/bench/baseline

# 3. физика в продукт
nexus serve --host 127.0.0.1 --port 8000 --api-key $KEY
#   → бейдж «замкнута / масса / стенка / запас прочности» в карточке модели

# 4. логирование процесса (SQL выше) и три кнопки обратной связи
```

Через неделю у вас будет: цифра «сколько процентов генераций большой LLM вообще
пригодны», физический бейдж как отличие продукта и корпус, который начнёт расти
правильными данными. Это и есть фундамент собственной модели.
