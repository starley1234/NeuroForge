# Что получилось: архитектура простыми словами

Документ отвечает на два вопроса: **как это устроено** и **что из этого реально
работает** (с измерениями, а не с обещаниями).

---

## 1. Идея в трёх предложениях

Обычная LLM видит мир как ленту токенов: картинка — нарезка на квадратики, звук —
спектрограмма, деталь — текст описания. NEXUS устроен иначе: любой сигнал сначала
переводится в **общее физическое пространство** (координаты в метрах, время в
секундах, масса, сила), и только потом попадает в ядро. Ядро вместо растущего
KV-кэша держит **память фиксированного размера**, которая обучается прямо во
время чтения, а проверяет свои идеи не текстом, а **расчётом прочности**.

## 2. Как работает конвейер

```
        ТЗ / код          звук, видео        деталь OpenSCAD      облако точек, IMU, ЭКГ
            │                  │                    │                      │
     ┌──────▼──────┐   ┌───────▼───────┐   ┌────────▼────────┐   ┌─────────▼─────────┐
     │ AST-BPE     │   │ SSM по Δt     │   │ CSG → SDF →     │   │ Neural-ODE фильтр │
     │ токенизатор │   │ (реальные сек)│   │ B-Rep граф      │   │ по реальному Δt   │
     └──────┬──────┘   └───────┬───────┘   └────────┬────────┘   └─────────┬─────────┘
            └──────────────────┴────────────────────┴──────────────────────┘
                                          │
                        ┌─────────────────▼──────────────────┐
                        │  Общая шина: к каждому токену       │
                        │  добавлены x,y,z (м), t (с),        │
                        │  масса (кг), сила (Н)               │
                        └─────────────────┬──────────────────┘
                                          │
        ┌─────────────────────────────────▼─────────────────────────────────┐
        │  Слой ×N:                                                          │
        │   1) Fast-Weights память  — конспект всего прочитанного,           │
        │      размер не зависит от длины контекста                          │
        │   2) Окно внимания        — точная работа с последними W токенами  │
        │   3) Разреженные эксперты — из 32 «специалистов» работают 5        │
        └─────────────────────────────────┬─────────────────────────────────┘
                                          │
                        ┌─────────────────▼──────────────────┐
                        │ Латентный цикл: до k проходов       │
                        │ «про себя», можно спросить FNO-     │
                        │ критика «эта деталь выдержит?»      │
                        └─────────────────┬──────────────────┘
                                          │
              ┌───────────────────────────┴───────────────────────────┐
              │ токены (OpenSCAD, текст, код)   поля σ, траектории, масса │
              └───────────────────────────────────────────────────────┘
```

### Что здесь делает каждый блок

| Блок | Простыми словами | Обычная альтернатива |
| :-- | :-- | :-- |
| **Общая шина** | «этот кусок данных случился на 0.4 с позже и находится в 3 см правее» | всё склеено в одну ленту, порядок = позиция токена |
| **Fast-Weights память (TTT)** | конспект: маленькая матрица, которую модель дописывает по ходу чтения по правилу «ошибся — подправь» | KV-кэш: помнит всё дословно, память растёт линейно |
| **Гейт новизны** | однообразный сигнал почти не пишется в конспект | каждый токен стоит одинаково |
| **Окно внимания** | точная память о последних W токенах | полное внимание, стоимость O(N²) |
| **Разреженные эксперты** | из 32 «специалистов» на токен работают 5 | один общий FFN на всё |
| **Латентный цикл** | подумать несколько раз «про себя» перед ответом | выписать рассуждение текстом (10k токенов) |
| **FNO-критик** | быстрая прикидка «выдержит ли деталь» внутри рассуждения | никакой проверки, только правдоподобие текста |
| **Физический контур** | реальный МКЭ и аудит технологичности как источник наград | оценка «нравится/не нравится» другой моделью |

## 3. Что измерено (а не обещано)

### O(1) память — работает

`nexus needle --lengths 1024,8192,65536`

| Контекст | Состояние NEXUS | KV-кэш обычной модели | Выигрыш |
| --: | --: | --: | --: |
| 1 024 | 0.042 МБ | 1.1 МБ | ×27 |
| 8 192 | 0.042 МБ | 9.0 МБ | ×214 |
| 65 536 | 0.042 МБ | 72 МБ | **×1710** |

Извлечение «иглы» из конспекта на необученных весах: cos 0.45–0.64. То есть
механизм работает сам по себе, до всякого обучения.

### Вклад блоков — измеряется командой `nexus ablate`

Прогон 120 шагов, модель 1.5M, корпус «инженерный текст + математика»
(CPU, одинаковый seed):

| Вариант | Параметры | val_ppl | ток/с | Состояние 4k / 16k |
| :-- | --: | --: | --: | :-- |
| полная | 1 564 538 | 52.84 | 756 | 43.1 / 43.1 КБ |
| без TTT-памяти | 1 526 126 | 54.53 | 1 286 | 36.0 / 36.0 КБ |
| без окна внимания | 1 481 306 | 57.26 | 950 | 7.1 / 7.1 КБ |
| плотный FFN вместо MoE | 905 594 | 54.74 | 1 055 | 43.1 / 43.1 КБ |
| без латентного цикла | 1 564 538 | **52.69** | 823 | 43.1 / 43.1 КБ |

Честные выводы из этой таблицы:

* **Окно внимания — самый нужный блок**: без него качество падает сильнее всего (+8 %).
* **TTT-память помогает** (+3 % к качеству), но стоит 40 % скорости. На длинном
  контексте её ценность должна расти — на 256 токенах она просто не нужна.
* **MoE на такой малышке не окупается**: +73 % параметров ради +3.6 % качества.
  Разреженные эксперты имеют смысл от сотен миллионов параметров.
* **Латентный цикл пока ничего не даёт** — вариант без него оказался чуть лучше.
  Ему нужен обученный FNO-критик и задачи, где есть что проверять.

Это прогон на 120 шагов и игрушечной модели: выводы верны *для этого масштаба*, а
не вообще. Но именно так и надо проверять архитектуру — а не верить схеме.

### Физика — сверена с аналитикой

| Проверка | NEXUS | Аналитика | Расхождение |
| :-- | --: | --: | --: |
| σ в брусе 10×10×40 мм под 500 Н | 4.45 МПа | 5.00 МПа | 11 % |
| прогиб того же бруса | 0.00266 мм | 0.0029 мм | 8 % |
| толщина стенки плиты 3 мм | 3.04 мм | 3.00 мм | 1 % |
| толщина стенки трубы 2 мм | 2.17 мм | 2.00 мм | 8 % |
| масса куба 20 мм из АМг6 | 20.7 г | 21.6 г | 4 % |

Расхождения — от воксельной дискретизации; они систематические и уменьшаются с
сеткой. Для наград в обучении этого более чем достаточно.

### Данные — генерируются сами

`nexus flywheel -n 5000`: 100 % компилируется, 92–98 % проходит аудит manifold,
все валидные детали получают тензор напряжений. Плюс `nexus gen-math` — 13 типов
инженерных задач, где ответ считает формула, а не модель.

## 4. Что здесь новое, а что — стандарт

**Стандартные (проверенные другими) кирпичи:** скользящее окно внимания с GQA и
RoPE, разреженные MoE, byte-level BPE, matrix-free CG для МКЭ, GRPO для RL.
Это не изобретение, и хорошо: они работают.

**Собственно наше:**

1. **Физический верификатор в контуре обучения.** Модель получает награду не за
   правдоподобный текст, а за деталь, которая компилируется, печатается и держит
   нагрузку. Ни один публичный CAD-датасет таких меток не содержит.
2. **Единая шина с физическими инвариантами** — координаты, время в секундах,
   масса и сила как часть каждого токена.
3. **Гейт новизны в TTT-памяти**: однообразный сигнал почти не тратит память —
   именно это даёт recall 0.45 на 64k контекста у необученной модели.
4. **Замкнутый маховик**: генератор деталей → МКЭ → обучение → модель генерирует
   новые детали → снова МКЭ. Данные не заканчиваются.

**Гипотезы, которые ещё не подтверждены:** латентные рассуждения вместо CoT,
польза TTT на длинном контексте, работа MoE на нашем масштабе, перенос между
модальностями при замороженном ядре.

## 5. Где мы на самом деле находимся

| Стадия | Состояние |
| :-- | :-- |
| Архитектура и код | готово, 114 тестов, всё считается и обучается |
| Инженерный контур (CAD + МКЭ + награды) | готово и сверено с аналитикой |
| Данные | генерируются бесконечно + каталог открытых корпусов |
| Инфраструктура (реестр, API, приёмка, откат) | готово |
| **Обученная модель** | **нет** — это следующий и самый дорогой шаг |
| Доказательство преимущества над обычным трансформером | частично: есть абляции на игрушечном масштабе |

Прямая аналогия: построен завод — станки, конвейер, ОТК, склад. Продукции пока
нет, потому что первую партию сейчас как раз запускают.

## 6. Что делать дальше по порядку

1. Дождаться `--scale gpu` (идёт сейчас) и посмотреть `val_ppl` и
   `scad_compile_rate` — первый настоящий сигнал.
2. `nexus ablate --preset small --steps 3000 --seq-len 1024` на GPU: те же
   вопросы, но на осмысленном масштабе и длинном контексте. Если TTT-память там
   не выигрывает — её надо чинить или убирать, а не защищать.
3. Транслятор CadQuery→OpenSCAD: открывает 1M+ готовых программ.
4. RL-фаза на физических наградах — то, ради чего всё и строилось.
