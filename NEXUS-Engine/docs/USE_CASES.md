# Сценарии применения и развитие продукта

Коротко: что с этим можно делать уже сегодня, что — после обучения модели, и
куда продукт растёт дальше.

---

## 1. Что работает прямо сейчас (без обученной модели)

Движок геометрии и прочности самодостаточен — он не требует нейросети.

### 1.1 Проверка детали перед печатью или фрезеровкой

Загрузили `.scad` — получили массу, центр масс, замкнутость, толщину стенок,
свесы, достижимость фрезой и запас прочности под нагрузкой.

```bash
nexus analyze part.scad --material alu6061 --force 0 0 -400 --stl out.stl
```

Кому: конструктор, мейкер, технолог. Заменяет ручную прикидку «выдержит ли».

### 1.2 Пакетный аудит библиотеки моделей

Прогнать сотни деталей и найти те, что не печатаются или не держат нагрузку.

```bash
for f in parts/*.scad; do nexus reward "$f" --safety 2.0; done
```

Кому: производство, где накопилась библиотека из сотен файлов.

### 1.3 Инструменты для чужой LLM (MCP)

Claude, GPT или локальная модель получают доступ к нашему движку: пишут
OpenSCAD, тут же проверяют массу и прочность, исправляют и сохраняют результат.

```jsonc
{"mcpServers": {"nexus": {"command": "python", "args": ["-m", "nexus.mcp.server"]}}}
```

Кому: тот, у кого уже есть подписка на сильную модель и нужен «CAD-калькулятор»
в диалоге. Работает сегодня, без нашей модели.

### 1.4 Превращение своей базы моделей в датасет

Если на сайте копятся пары «запрос пользователя → сгенерированный OpenSCAD»,
`nexus ingest` делает из них обучающий корпус с физическими метками, а
`nexus render-dataset` — выборку картинок для визуальной модальности
([INGEST.md](INGEST.md)).

### 1.5 Генерация датасетов

Бесконечный поток кортежей «ТЗ → код → 3D → поле напряжений» и верифицированной
инженерной математики.

```bash
nexus flywheel -n 5000
nexus gen-math -n 50000
nexus collect --teacher command --command "claude -p" -n 500
```

Кому: исследователь, который обучает свою модель; данных с физическими метками
в открытом доступе нет.

### 1.6 Автоподбор параметров под нагрузку

```bash
nexus optimize part.scad --force 0 0 -350 --material pla --safety 3.0 --budget 40
```

Generative design без облака: перебор вариантов с настоящим МКЭ, минимизация
массы при заданном запасе прочности. Габариты и присоединительные размеры не
меняются.

### 1.7 Сервис в закрытом контуре

HTTP API с документацией, версиями моделей и фоновым обучением — разворачивается
в локальной сети, ничего наружу не уходит.

```bash
docker compose up -d      # http://localhost:8000/docs
```

Кому: предприятия, где чертежи нельзя отправлять во внешние облака.

## 2. Что появится после обучения модели

| Сценарий | Как выглядит | Что нужно |
| :-- | :-- | :-- |
| **ТЗ → деталь** | «кронштейн под 350 Н, алюминий, крепление на 4 болта M5» → готовый параметрический код | прогон `--scale gpu` |
| **Правка по словам** | «сделай стенку 3 мм и добавь ребро жёсткости» → изменённый код | тот же прогон + датасет правок |
| **Оптимизация** | модель сама перебирает варианты, пока запас ≥ 2 и масса минимальна | RL-фаза на физических наградах |
| **Объяснение отказа** | «деталь треснет у отверстия, потому что там перемычка 1.1 мм» | связка поля σ и текста |
| **Подсказка в CAD** | плагин к OpenSCAD/FreeCAD с проверкой на лету | обёртка над готовым API |

## 2.1 Чего делать не стоит

Разведка рынка ([LANDSCAPE.md](LANDSCAPE.md)) показывает: ниша «ещё один
text-to-CAD» занята (Zoo.dev, AdamCAD с миллионом моделей и экспортом в SCAD,
Leo AI). Соревноваться там не нужно. Свободно другое — **физическая проверка
сгенерированной детали**: конкуренты награждают модель за сходство картинок и
исполнимость кода, но не за то, что деталь выдержит нагрузку и напечатается.

## 3. Как развивать: три горизонта

### Горизонт 1 — ближайшие недели (сделать модель полезной)

1. **Обучить `--scale gpu`** и посмотреть `val_ppl` и `scad_compile_rate`.
2. **Транслятор CadQuery → OpenSCAD** (2–3 дня) — открывает 1M+ готовых программ
   из открытых датасетов. Самый дешёвый способ получить объём данных.
3. **Абляции на длинном контексте** (`nexus ablate --preset small --seq-len 1024`) —
   решить судьбу TTT-памяти: выигрывает или убираем.
4. **RL на физических наградах** — то, ради чего всё строилось.

### Горизонт 2 — месяцы (сделать продукт)

5. **Веб-интерфейс**: поле ТЗ → код → 3D-просмотр → карта напряжений → кнопка
   «скачать STL/STEP». Сейчас всё это есть в API, не хватает витрины.
6. **Marching cubes и STEP/IGES** — экспорт в формат, который примет любой CAD.
7. **Плагины**: OpenSCAD, FreeCAD, VS Code. Модель работает там, где конструктор
   уже сидит.
8. **Ускорение**: Triton-ядра для TTT/MoE, батч-инференс — 3–10× к скорости.

### Горизонт 3 — дальше (то, ради чего архитектура)

9. **Вторая модальность**: заморозить ядро, обучить лёгкий энкодер (чертёж,
   фотография детали, звук работающего механизма). Проверка главной гипотезы
   о переносе.
10. **Сборки, а не отдельные детали**: контакты, зазоры, кинематика.
11. **Робототехника**: та же шина с координатами и временем, но выход —
    траектории; движок прочности становится симулятором.

## 4. В каком виде это может жить

| Форма | Кому | Состояние |
| :-- | :-- | :-- |
| CLI + библиотека Python | инженеры, исследователи | готово |
| HTTP API в контуре предприятия | КБ, производство | готово |
| MCP-инструменты для чужих LLM | пользователи Claude/GPT | готово |
| Веб-сервис «ТЗ → деталь» | мейкеры, малые КБ | нужен горизонт 2 |
| Плагин к CAD | конструкторы | нужен горизонт 2 |
| Обученные веса под лицензией | все | нужен горизонт 1 |

---

## 5. По чему мерить прогресс

| Метрика | Сейчас | Цель |
| :-- | :-- | :-- |
| `scad_compile_rate` — доля генераций, которые собираются | 0 | > 0.8 |
| Доля деталей, проходящих аудит manifold | — | > 0.9 |
| Доля деталей с запасом прочности ≥ 2 | — | > 0.7 |
| `val_ppl` относительно словаря | ~0.8 × словаря | < 0.005 × словаря |
| Время «ТЗ → проверенная деталь» | — | < 60 с |

Первые три — главные: они означают, что модель делает не текст, похожий на CAD,
а детали, которые реально можно изготовить.
