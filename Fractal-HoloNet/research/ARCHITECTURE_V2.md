# ELAST-HOLO — проект архитектуры v2
**Рабочее название: Elastic-Time Holographic Associative Machine (ELAST-HOLO)**

> Как модифицировать Fractal-HoloNet, чтобы получилась архитектура с реальной
> новизной и доказуемым существенным преимуществом. Документ — рабочий,
> подлежит ревизии после каждого эксперимента.

---

## 0. TL;DR

Текущее ядро CRAC — это диагональная линейная рекурренция с комплексным
затуханием (семейство LRU / RetNet / HGRN). С 2023 года поле ушло далеко
вперёд (Gated DeltaNet, RWKV-7, DeltaProduct, TTT, Titans, Palimpsa, MARCH).
Поэтому v2 строится на трёх ставках:

1. **Структурное (непаритетное) преимущество** — нативное упругое
   (нерегулярное, событийное) время. Это домен, где токенизаторы и attention
   проигрывают по построению, а текущая модель уже наполовину там живёт.
2. **Управляемая память** — дельта-запись с фазовой ортогонализацией +
   двухчасовая (fast/slow) голографическая память с сюрприз-гейтом:
   recall уровня attention при константном состоянии O(1).
3. **Эффективность** — O(N) обучение (ассоциативный скан) и O(1) инференс
   с полноранговым смешиванием каналов через циркулянт (FFT).

Новизна — не в отдельных кирпичах, а в комбинации, которой в литературе нет
(раздел 5): комплексно-фазовый домен + упругое время + дельта-запись +
двойные фазово-когерентные часы + итеративное чтение.

## 1. Диагноз: что именно ограничивает текущий CRAC

| # | Ограничение | Следствие |
|---|---|---|
| 1 | **Диагональная динамика**: каждый канал состояния эволюционирует независимо, смешивание каналов отложено в FFN | Экспрессивность ниже, чем у трансформера на токен; нужен «переход токен→канал» внутри ядра |
| 2 | **Одна фиксированная шкала времени на канал** (ω обучаемая, слабо модулируемая входом) | Канал не может «замедлиться» под длинную зависимость; локальное/дальнее не переключается по контексту |
| 3 | **Запись без адресации**: `s += k⊙v` — только суперпозиция, нет вычитания/затирания устаревшего | Интерференция коллизий; память деградирует на длинных контекстах |
| 4 | **Линейное чтение**: `out = q ⊙ Re(s)` — фиксированная линейная карта состояния, нет выравнивания query↔key, нет итеративного уточнения | Слабый ассоциативный recall (MQAR-класс задач проваливается) |
| 5 | **Один стейт на всё** | Нет разделения «рабочая память / эпизодическая память», нет консолидации |
| 6 | Фаза используется только как вращение | Комплексная фаза не используется как *адресное пространство* для связывания key→value |
| 7 | Последовательный Python-цикл | На GPU обучение неконкурентно, даже при O(N) асимптотике |

## 2. Где сейчас фронтир (2025–2026)

Короткая карта того, с чем придётся конкурировать и от чего отстраиваться:

- **Gated DeltaNet** (ICLR 2025): дельта-правило с форгет-гейтом, матрицы
  Householder `I − β k kᵀ` — «запись с вычитанием» уже существует в вещественном домене.
- **RWKV-7**: динамическая эволюция состояния, векторный decay, векторная
  in-context learning rate, разные ключи на удаление/замену. Бьёт transformer
  на MAD-бенчмарке, обгоняет FlashAttention-3 по скорости с ~4096 токенов.
- **DeltaProduct**: несколько (n_h) шагов Householder-обновления на токен —
  то есть **многошаговая запись**. Многошаговое *чтение* осталось незанятым.
- **TTT-Linear**: обновление скрытых весов на тест-тайме — адаптация без роста памяти.
- **Titans**: сюрприз-метрика для консолидации памяти — гейт «что запомнить в долгую память» известен.
- **Palimpsa** (ICML 2026): метапластичность (Байесово управление забыванием) — «как именно забывать» стало отдельным механизмом.
- **MARCH** (авг. 2026): content-routed якоря состояния — маршрутизация по банкам памяти.
- **BLA, ARMT**: гибриды окна и рекуррентности, тест-тайм дообучение.

**Вывод для нас:** простые апгрейды диагональной рекурренции (gating, decay,
multi-scale) уже заняты. Новизна возможна по двум осям:
(а) перенос delta-rule/Titans-механизмов в **комплексно-фазовый домен** с
фазовым связыванием, (б) **упругое время** — управляемый сетью темп
внутренних часов, чего нет ни в одной из перечисленных работ.

## 3. Главная ставка: где преимущество может быть непаритетным

Честно: на текстовом LM-лоссе при равных параметрах новая маленькая
архитектура получит *паритет*, а не кратный выигрыш — трансформеры
гипероптимизированы. Поэтому заявляем два класса преимуществ:

- **Класс A (структурное).** Непрерывные/событийные потоки с нерегулярной
  дискретизацией: физиологические сигналы с пропусками (PhysioNet),
  событийные камеры, тики с переменной частотой, аудио с variable rate.
  Токенизатор здесь структурно неприменим (нужна ресемплинг-интерполяция,
  которая и есть главный источник ошибки), attention — неприменим по
  вычислительной стоимости. ELAST-HOLO принимает `(t, x)` нативно.
- **Класс B (эффективность + память).** При сопоставимом качестве:
  O(N) обучение, O(1) состояние на инференсе, константная память на сколь
  угодно длинной сессии, тест-тайм адаптация без роста состояния.

## 4. Механизмы архитектуры

### M1. Упругое время (elastic clock) — сердце новизны

Сеть сама управляет темпом своих внутренних часов:

```
Δθ_t  = Δ_min + (Δ_max − Δ_min) · σ(W_Δ x_t)          # приращение фазы на токен
θ_t   = θ_{t-1} + Δθ_t                                # глобальный "набег фазы"
Ω_t   = base_ω ⊙ Δθ_t                                 # мгновенная частота канала
```

Свойства:

- **Обучаемое «замедление»**: для длинной зависимости канал получает малый
  Δθ (медленная намотка фазы = долгая память), для локальной синтактики —
  большой. Шкалы времени становятся *контекстно-зависимыми*, а не фиксированными.
- **Нерегулярная дискретизация нативно**: если известны внешние интервалы
  Δt_i между отсчётами, они подставляются в набег фазы напрямую — никакой
  интерполяции и ресемплинга. Пропуски данных = умножение фазы, а не «паддинг».
- **Событийный режим**: при пропуске шага состояние не трогается, фаза
  доворачивается на Δθ·(число пропущенных шагов) — точная фазовая динамика.
- **Стабильность**: Δ_min/Δ_max из лог-пространства, инициализация Δθ≈1
  (совпадает с обычной дискретной рекурренцией в старте).

Это переносимая в аналог идея «непрерывного времени» (neural ODE), но в
дискретной, обучаемой и стабильной форме. В литературе линейных рекурренций
такого механизма нет — это и есть ключевая заявка на новизну.

### M2. Спектральное смешивание каналов (циркулянт, FFT)

Уход от диагональности без O(D²): матрица перехода — циркулянт C,
диагонализуемый через FFT:

```
s_t = (γ_t ⊙ C(φ_t)) s_{t-1} + w_t,   C = F⁻¹ diag(ĉ) F
```

- Полное токен↔канальное смешивание за O(D log D) вместо O(D²).
- Обучаемый спектр ĉ (мало параметров: D комплексных коэффициентов на слой).
- В стриминговом режиме шаг стоит O(D log D) — для D=128..256 это доли
  миллисекунды; для эдж-инференса предусмотрен «диагональный режим»
  (M2 off), чтобы честно сохранять O(D) на шаг.

### M3. Комплексная дельта-запись с фазовой ортогонализацией

```
s_t = γ_t ⊙ s_{t-1} + β_t ⊙ ( k_t v_tᴴ − k_t (k_tᴴ s_{t-1}) )
```

- `kᴴ` — эрмитово сопряжение (в комплексном домене это честное скалярное
  произведение). Запись *вычитает проекцию существующей памяти на новый
  ключ* — коллизии затираются, а не накапливаются.
- Векторный `β_t` (in-context learning rate) и отдельные ключи на
  удаление/замену — как в RWKV-7, но в комплексном домене с фазовым сдвигом
  проекции перед вычитанием («фазово-корректированное стирание»).
- Итог: ассоциативная запись уровня DeltaNet/Gated DeltaNet + фаза как
  адресное пространство (голографическое связывание key→value).

### M4. Двухчасовая голографическая память (fast/slow)

```
s_fast ← γ_fast ⊙ s_fast + write(...)        # рабочая память, γ ∈ [0.5, 0.9]
surprise_t = |k_tᴴ s_fast|² / norm           # новизна ключа
η_t = σ(surprise_t · w + b)                  # гейт консолидации
s_slow ← (1 − η_t·(1−γ_slow)) ⊙ s_slow + η_t · write(...)   # эпизодическая память
```

- «Сюрприз» решает, что достойно долгой памяти (родственно Titans), но обе
  памяти **вращаются одним упругим таймером** — фазовая когерентность
  fast/slow, чего нет у вещественных аналогов.
- Чтение: обучаемый роутер α_t = σ(W_α x_t) смешивает отклики обеих памятей.
- Это же решает проблему «забывания редких фактов»: редкий, но сюрпризный
  факт консолидируется в slow-стейт и не вымывается потоком.

### M5. Итеративное ассоциативное чтение (фиксированный бюджет)

```
out⁰ = W_o [ q_t ⊙ Re(s) ; Im(s) ]
outⁱ⁺¹ = f( W_q outⁱ + W_m Re(s) + W_r q_t ),   i = 0..K−1,  K = 2..3
```

- Несколько шагов fixed-point уточнения (современные сети Хопфилда) на
  стороне чтения; бюджет константен → сложность шага остаётся O(1) по T.
- Аналог с точностью до наоборот: DeltaProduct делает многошаговую *запись*,
  мы — многошаговое *чтение*. Ниша свободна.
- Даёт нелинейную силу извлечения: «спросить у памяти несколько раз с
  уточнением», интерпретируемо через энергетическую функцию.

### M6. Тест-тайм консолидация (TTT-lite, опциональный модуль)

Маленький LoRA-подобный адаптер + онлайн-градиентный момент; обновление
каждые K токенов инференса. Память O(1), адаптация к пользователю/задаче
на лету (родственно TTT-Linear, но поверх ELAST-HOLO ядра).

### M7. Сигнальный фронтенд: аналитический вейвлет-банк

- Каждый канал: пара (реальный фильтр, фильтр Гильберта) → сразу комплексный
  вход, согласованный с комплексным ядром.
- Learnable cut-off + anti-aliasing: честная обработка произвольной частоты
  дискретизации; переменный Δt прокидывается в M1.

### Псевдокод ядра (шаг стриминга)

```python
def step(self, x, state):                       # x: (B, D) комплексный или пара (re, im)
    s_fast, s_slow, theta = state
    q, k, v, dg, db, ddt = self.in_proj(x)      # fused проекции
    gamma  = sigmoid(dg + bias)                 # векторный decay
    beta   = sigmoid(db)                        # векторная скорость записи
    dtheta = dmin + (dmax - dmin) * sigmoid(ddt)
    theta  = theta + dtheta
    omega  = self.base_omega * dtheta
    rot    = gamma * exp(1j * omega)            # комплексное вращение
    s_fast = rot * s_fast + beta * (k * v.conj() - k * (k.conj() * s_fast))  # M3
    eta    = sigmoid(self.surprise_proj(|k.conj() * s_fast|))                  # M4
    s_slow = (1 - eta * (1 - gamma_slow)) * s_slow + eta * beta * k * v.conj()
    out = self.iter_read(q, s_fast, s_slow)      # M5: 2–3 fixed-point шага
    return out, (s_fast, s_slow, theta)
```

## 6. План доказательства преимущества

**Синтетика (быстрые, интерпретируемые):**
- MQAR (multi-query associative recall), MAD, RegBench, Needle-in-a-Haystack
  с экстраполяцией длины (обучаем на 4K, тестируем 32K).

**Язык (честный matched-parameter протокол):**
- TinyStories → корпус ~10B токенов; равные параметры против
  Transformer++, Mamba-2, Gated DeltaNet, RWKV-7.
- LongBench / BABILong / RULER.

**Уникальный домен (непаритетная ставка):**
- PhysioNet (ЭКГ с пропусками), UCI irregular time series, событийное аудио,
  тиковые данные с переменной частотой. Метрика: ошибка прогноза *без*
  ресемплинга против лучших пайплайнов «интерполяция + токенизация».

**Эффективность:**
- токенов/сек на обучении и инференсе против FlashAttention-3 (на длинах
  4K–64K), память состояния, латентность шага.

**Тест-тайм адаптация:**
- персонализация на лету (few-shot в потоке) без роста памяти.

**Порог «существенности» (зафиксировать до экспериментов):**
- MQAR: ≥ +5 п.п. точности к лучшему линейному базлайну при ≤50% параметров;
- LM: паритет ppl при 2–3× меньших FLOPs на инференсе;
- Нерегулярный домен: ≥20% относительного выигрыша против
  «интерполяция + лучший линейный бейзлайн».

### Выводы прогона (честные)

1. **M3 необходим для recall**: v1 (диагональная рекурренция) застревает на
   уровне случайного угадывания независимо от бюджета; v2 обучается
   механизму (train-acc до 0.66 на L=24) и обобщает (val 0.26) при равных
   параметрах и одинаковом взвешивании query-позиции (×8, одинаково для
   обеих моделей — стандартный приём MQAR-обучения).
2. **Дальняя экстраполяция — открытая проблема**: оба варианта деградируют
   на L=96 (затухание γ^T и фазовый дрейф накапливаются). Следующий шаг —
   γ→1-каналы с жёсткой стабилизацией и фазово-инвариантная запись.
3. **Первый вариант M3 (поэлементный erase) расходился в NaN** — нормировка
   ключей и матричное состояние (rank-1, как Gated DeltaNet/RWKV-7) решили
   проблему. Урок: без нормировки отражатель `I−kkᴴ` расширяющий.
4. **Цена матричного состояния**: O(D²) на шаг и O(T·B·D²) активаций в
   последовательном autograd-графе — на CPU это ограничивает батч (16×64
   при D=64). Параллельный скан/chunked-обучение — приоритет P2.
5. **M1 работает**: +11.8% MSE на нерегулярной дискретизации при равных
   параметрах — упругое время даёт измеримый выигрыш там, где токенизатор
   и attention неприменимы по построению.

### Отклонения от исходного плана

- M3 реализован как **матричное состояние** (диагональ+rank-1), а не
  диагональное: поэлементная версия не решала MQAR. Это совпадает с
  формулой `k vᴴ − k(kᴴ s)` из раздела 4 (vᴴ — ко-вектор).
- Ассоциативный скан для матричного состояния отложен в P2 (rank-1-часть
  требует outer-product сегментного скана, как в RWKV-7/Gated DeltaNet).
- M6 (TTT-lite) не реализован в этом прогоне (оставлен на P3).

Правило процесса: **каждый механизм включается отдельной абляцией**, иначе
нельзя будет сказать, за счёт чего выигрыш.

---

## 8. Риски и митигация

1. **Стабильность M1** (набег фазы может взорваться/занулиться). Митигация:
   лог-параметризация Δ, узкий диапазон [0.2, 3.0], инициализация Δθ≈1,
   clip градиента; M1-абляция отдельно.
2. **M2 ломает параллельный скан** (циркулянт не сканируется поэлементно).
   Митигация: сначала chunked-обучение; скан в спектральном домене — открытая
   исследовательская задача (это и есть риск-ставка).
3. **M5 удорожает шаг**. Митигация: K=2–3 жёстко, shared W_q между итерациями.
4. **Опередят**: поле горячее (MARCH вышел в августе 2026). Митигация:
   еженедельный мониторинг arXiv, фокус на связке M1+M7, которой ни у кого нет.
5. **Завышенные ожидания**: без matched-parameter сравнений никаких заявлений
   о «превосходстве» — только измеренные числа.
