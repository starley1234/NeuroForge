# Что в NeuroSCAD является «моделью»

## Короткий ответ

Сейчас в репозитории **нет обученных нейросетевых весов**.

Есть готовый продуктовый конвейер:

```text
Текст пользователя
  → детерминированный распознаватель семейства и размеров
  → типизированный CSG-IR
  → проверка ограничений
  → OpenSCAD
  → STL и проверка сетки
```

То есть мы создали **обвязку, CAD-ядро, генераторы эталонных ответов и систему обучения**, но ещё не обучили и не подключили neural model.

Это сделано намеренно: сначала нужен надёжный формат правильного ответа и способ автоматически проверить результат. Иначе нейросеть будет быстро генерировать геометрию, качество которой невозможно измерить.

## Что умеет система сейчас без нейросети

Она распознаёт три семейства:

1. Разрезной хомут для трубы.
2. Монтажную пластину с четырьмя отверстиями.
3. Цилиндрическую втулку.

Для них система извлекает размеры, строит параметрический CSG-граф, генерирует SCAD и проверяет инженерные связи. Например, внутренний диаметр втулки не может быть больше допустимого относительно наружного, а отверстия пластины не должны выходить за края.

Это не «понимание любой детали». Это надёжные параметрические генераторы для известных семейств.

## Зачем тогда нужна нейросеть

Нейросеть заменит текущие регулярные выражения и ручной выбор шаблона. Она должна научиться:

- понимать разные формулировки одной задачи;
- выбирать подходящее семейство и конструкцию;
- восстанавливать пропущенные параметры как явно отмеченные предположения;
- выдавать CSG-IR, а не произвольный код.

Компилятор, ограничения, OpenSCAD и валидатор останутся детерминированными. Нейросети нельзя доверять окончательное решение о валидности детали.

## Как создаётся синтетический датасет

Для каждой записи программа делает следующее:

1. Выбирает семейство: хомут, пластина или втулка.
2. Случайно выбирает физически допустимые размеры.
3. Создаёт русское или английское текстовое описание.
4. Строит эталонный CSG-IR известным генератором.
5. Проверяет IR и инженерные ограничения.
6. Сохраняет пару `текст → правильный IR` в JSONL.

Пример:

```text
Вход:  "Втулка 20/8, высота 15 мм"
Выход: difference(цилиндр Ø20, отверстие Ø8), высота 15
```

Похожие фразы одной и той же геометрии помещаются только в один split. Это не даёт модели увидеть почти ту же деталь при обучении и затем получить завышенную оценку на тесте.

## Какое обучение требуется

Первый практический этап — LoRA fine-tuning небольшой code model около 1.5B параметров:

```text
текст → JSON CSG-IR
```

Для старта достаточно 10–50 тысяч качественных синтетических примеров по 5–10 семействам. Но количество само по себе ничего не гарантирует. Нужны:

- разнообразные формулировки;
- реальные пользовательские запросы в отдельном тесте;
- целые семейства, полностью исключённые из train для проверки обобщения;
- constrained decoding по JSON Schema;
- render и geometry tests для предсказаний.

После SFT можно добавить preference tuning на основании точных геометрических метрик. Начинать с RL до получения сильного supervised baseline нецелесообразно.

## Чего реально можно добиться

Реалистичная первая production-цель:

- 5–10 поддерживаемых семейств деталей;
- не менее 99% structurally valid IR;
- не менее 95% успешных renders на поддерживаемом диапазоне;
- точное извлечение явно заданных размеров;
- обязательный вопрос пользователю при критически недостающих данных;
- генерация за секунды, а изменение ползунков — почти мгновенно.

Нереалистично обещать на первом этапе:

- произвольную механическую деталь по одной фразе;
- гарантированную прочность без нагрузок и материала;
- сертифицированную производственную готовность;
- 100% правильную геометрию только благодаря валидному JSON;
- STEP из OpenSCAD без отдельного B-Rep backend.

## Когда можно сказать, что модель создана

Только после появления:

1. versioned model weights;
2. inference adapter, подключённого к API;
3. benchmark report на закрытом test set;
4. geometry regression report;
5. безопасного fallback на текущие детерминированные генераторы.

До этого корректная формулировка: **создан CAD pipeline и training pipeline, neural model подготовлена к обучению, но ещё не обучена**.
